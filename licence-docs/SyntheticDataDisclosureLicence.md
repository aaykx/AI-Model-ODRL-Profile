# SyntheticDataDisclosureLicence.ttl

**Use Case:** UC-10 — Proprietary Teacher → Synthetic Data → Open Model Trained on Synthetics  
**Expected Result:** ✗ ART. 53 DISCLOSURE GAP  
**Legal Basis:** EU AI Act Art. 53(1)(c); Recitals 107–110; Phi-1 (Gunasekar 2023); Orca (Mukherjee 2023)

---

## What Problem This Licence Solves

A growing number of AI models are trained not on raw human-generated text, but on **synthetic data produced by a proprietary teacher model**. Microsoft's Phi-1 (2023) was trained substantially on GPT-4 generated "textbook quality" content. Microsoft's Orca (2023) used GPT-4 to generate explanation traces. This approach is increasingly common because synthetic data can be generated at scale, curated for quality, and targeted at specific capabilities.

However, under EU AI Act Art. 53(1)(c), GPAI providers must publicly disclose summaries of their training data. **Recitals 107–110 explicitly include synthetic data generated by other models** in the definition of training content that must be disclosed. Simply listing "synthetic data" without identifying the teacher model or its own licence terms is insufficient.

The evasion strategy this use case targets: a developer uses GPT-4 to generate a synthetic corpus, trains an open model on it, and discloses the synthetic corpus as training data but omits the fact that it was generated by a proprietary teacher model. The `article50PolicyURL` exists but does not include the synthetic provenance chain.

---

## What the File Contains

The file defines a single ODRL `Policy` with **one constrained permission** (training on synthetic data, with disclosure duty) and **one prohibition** (training with undeclared synthetic provenance).

### Permission — AI Training on Synthetic Data With Provenance Disclosure

```turtle
odrl:permission [
    odrl:action aimd2:AITraining ;
    odrl:constraint [
        aimd2:dataGenerationMethod odrl:isA <https://raw.githubusercontent.com/aaykx/AI-Model-ODRL-Profile/main/AIMD_extended_v2.ttl#SyntheticFromProprietaryTeacher>
    ] ;
    odrl:duty [ odrl:action aimd2:ComplyWithArticle50 ] ;        # must declare teacher model
    odrl:duty [ odrl:action aimd2:InheritSourceProhibitions ] ;  # proprietary ToS flows through
]
```

Training on proprietary-teacher synthetics is permitted, provided:
- `ComplyWithArticle50` is fulfilled — the `article50PolicyURL` must specifically cover the synthetic data provenance (name the teacher model, the generation method, any applicable licence restrictions)
- `InheritSourceProhibitions` is fulfilled — the proprietary teacher's ToS restrictions (e.g. "do not train competing models") survive into the synthetic data layer and cannot be laundered away

### Prohibition — Training Without Synthetic Provenance Declaration

```turtle
odrl:prohibition [
    odrl:action aimd2:AITraining ;
    odrl:constraint [
        aimd2:dataGenerationMethod odrl:eq <https://raw.githubusercontent.com/aaykx/AI-Model-ODRL-Profile/main/AIMD_extended_v2.ttl#UndeclaredSynthetic>
    ] ;
]
```

If the `dataGenerationMethod` indicates undeclared synthetic origins, training is prohibited. In the test distribution `OpenModelSyntheticDist10`, the `dataGenerationMethod` is `"synthetic-from-proprietary-teacher"` and `article50PolicyURL` is **absent** — both the prohibition and the duty failure fire simultaneously.

---

## The `dataGenerationMethod` Operand

The `aimd2:dataGenerationMethod` left operand distinguishes:
- `"synthetic-from-proprietary-teacher"` — generated by a proprietary LLM (GPT-4, Claude, Gemini)
- `"real"` — human-generated content
- `"mixed"` — combination of real and synthetic
- `UndeclaredSynthetic` — synthetic origin known but not disclosed

This operand matters because GDPR's applicability changes with synthetic data (personal data concerns are reduced), but EU AI Act disclosure requirements increase. The same property serves both compliance frameworks.

---

## How the Checker Uses This File

`checkSyntheticDataDisclosure("OpenModelSyntheticDist10")`:
1. Finds `aimd2:dataGenerationMethod "synthetic-from-proprietary-teacher"` on the distribution
2. Checks `aimd2:article50PolicyURL` → **absent**
3. Detects the disclosure gap — synthetic provenance not in Art. 53 declaration
4. Returns `compliant: false`, `conflict: "art53-disclosure-gap: synthetic-from-proprietary-teacher without article50PolicyURL"`

## ODRL Terms Used

| Term | Type | Role in this Policy |
|---|---|---|
| `aimd2:AITraining` | `odrl:Action` | Governed activity |
| `aimd2:dataGenerationMethod` | `odrl:LeftOperand` | Synthetic vs real data discrimination |
| `aimd2:ComplyWithArticle50` | `odrl:Action` (duty) | EU AI Act Art. 53(1)(c) synthetic disclosure |
| `aimd2:InheritSourceProhibitions` | `odrl:Action` (duty) | Proprietary teacher's ToS restrictions survive |
| `aimd2:propagatesObligationTo` | `rdf:Property` | Synthetic disclosure obligation flows downstream |
